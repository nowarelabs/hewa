# @hewa/app-shell

The application shell every hewa console is built on: a title bar with view
tabs, a vertical icon rail, three collapsible side panels, and a status bar.

An app supplies a `ShellConfig` and gets all of it. The app decides **what** each
part shows; this package decides **where** they sit, what they look like, and
what they remember.

`apps/admin-dashboard` is the reference implementation.

## Using it

```bash
pnpm add @hewa/app-shell
```

Two lines in the app's global stylesheet:

```css
@import "tailwindcss";
@import "@hewa/app-shell/styles.css";

@source "../../node_modules/@hewa/app-shell/dist";
```

The `@source` line is not optional. Tailwind finds utility classes by reading
source, and this package's classes live in compiled `dist/index.mjs`, which
Tailwind does not scan by default.

The `exports` field is generated by `vp pack`, and it is easy to lose the
`./styles.css` entry: `exports: true` **rewrites the whole field** rather than
merging into it, so a hand-written `"./styles.css"` in `package.json` is gone the
first time the package is built, and the app then fails with
`"./styles.css" is not exported under the condition "style"`. The subpath is
therefore declared in `vite.config.ts` under `pack.exports.customExports`, and
the conditions are named explicitly because a bare string only matches a
resolver that treats a string as unconditional — a CSS import is resolved under
the `style` condition, so do not simplify that to a plain path.

Run `vp pack` in this package before building an app that consumes it.

Then render the shell:

```tsx
"use client";

import { AppShell } from "@hewa/app-shell";

import { config } from "./shell.config";

export default function App() {
  return <AppShell config={config} />;
}
```

The app needs a `NuqsAdapter` above the shell, because the shell mirrors the
open view, the selected rail item and the panel collapse state into the query
string. Pass `syncUrl: false` to render without one.

## What a config declares

```ts
export const config: ShellConfig = {
  brand: { name: "Admin", initials: "AD" },
  defaultView: "flights",
  syncUrl: true,
  actions: [{ id: "refresh", label: "Refresh", icon: RefreshCw, onSelect: reload }],
  views: {
    flights: {
      label: "Flights",
      longLabel: "Flight tracker",
      icon: Plane,
      rail: [
        {
          id: "all",
          label: "All flights",
          icon: Plane,
          panel: { title: "All flights", render: FlightListPanel },
        },
      ],
      main: { render: FlightTable },
      right: { title: "Flight details", render: FlightDetailsPanel },
      assistant: { title: "Assistant", render: AssistantPanel },
      status: {
        message: "Real-time aircraft monitoring",
        actions: [{ id: "filter", label: "Filter", icon: Filter, onSelect: openFilter }],
        zoom: { value: 100, onZoomIn, onZoomOut, onFit },
        savedAt: "Last saved 14:02",
      },
    },
  },
};
```

A view id is an ordinary string, not a union, so an app declares as many views
as it wants without editing this package. `assistant` is omitted rather than
rendered empty: a fourth column that is always a placeholder is a column nobody
looks at.

Panels take a `render` **component**, not an element, so a panel can hold state
and run effects. An element built once by the config is hoisted out of the render
cycle, and a collapsed panel that keeps a poller running is a battery cost with
no visible output.

## Colour

Every class this package paints is one of its own tokens: `bg-surface`,
`bg-surface-raised`, `text-ink`, `text-ink-muted`, `border-line`, `text-accent`.
No component here writes `neutral-900` or `gray-700`, and neither should an app
that uses the shell, because a hard-coded grey does not follow the `.dark` class
the shell toggles and the two themes drift apart on the first dark-mode bug.

`src/styles.css` holds both themes and the `@theme inline` block that maps them
onto Tailwind's colour scale. Change the palette there, in one place, for every
app at once.

## State

`ShellStateProvider` keeps the view, the rail selection, the three panel collapse
flags, and the theme. With `syncUrl` on, each is a query parameter, so a
console link reopens on the panel you were looking at. The old admin dashboard
serialised all seven rail selections into a single JSON query parameter and
`JSON.parse`d it on every render, unguarded; one truncated bookmark was a blank
screen.
